# Health model data is kept warm only while someone watches

The web app keeps a server-side snapshot and history tail of a health model, and pushes changes to browsers over Server-Sent Events, only while at least one signed-in user has that model open. It reads Azure with a current viewer's on-behalf-of token, shares the cached data between viewers of the same model, and admits each viewer only after an access check made as that viewer. Past history, which never changes, is also persisted so a restart does not fetch it again. A background collector running on the app's managed identity, as in cpu-health-demo, was rejected for now: it is always warm and can keep history beyond the API's retention, but it reads on the app's behalf rather than the user's, which ADR 0006 ruled out. The cost of this choice is that nothing is collected while nobody watches, and the first viewer after a quiet period waits for the tail. Alert webhooks for instant push were rejected because a state change already takes one to fifteen minutes to be evaluated, and a thirty-second poll adds little to that. The hub is built so that an app-identity collector for named models can be added later as configuration.
