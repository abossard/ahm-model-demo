# One Foundry hosted agent with health model skills and Azure MCP

All agent work runs in one Python hosted agent in Microsoft Foundry: a single Agent Framework agent that loads the health model skills of the Task type (healthmodel-analyze, healthmodel-plan and the local healthmodel-design-rules) and reads Azure through the Azure MCP server (`azmcp`, built from the branch that adds `monitor healthmodels inspect`). A Session maps to one Foundry conversation, which gives each Session its own sandbox with persistent files. The agent ships as a container image. That began because the `azmcp` binary exceeded the 250 MB limit of source-ZIP deployment; since ADR 0006 the MCP server is its own Container App, and the image stays because it carries the skill folders and a pinned runtime. A workflow of specialist agents inside the hosted agent was rejected: the skills already carry the method for each Task type, and one agent with skills is less code to keep in step with a pre-release hosting package. Foundry workflows were rejected because they retire on 2026-12-01. Several hosted agents linked over A2A were rejected because A2A calls to Foundry agents are text-only without streaming, which would hide steps from the activity timeline. Hosted agents require Sweden Central; North Europe is not supported.
