# Entra sign-in, and everything on behalf of the user

Users sign in with Entra ID, and the web app and the agent reach Azure only as that user through the OAuth 2.0 on-behalf-of flow. This replaces the public app of ADR 0002: Sessions are private to their user, and Apply is bounded by the user's own Azure RBAC instead of by this deployment's resource group. The web app's managed identity keeps only the session store, the call to the hosted agent, and the federated credential that stands in for a client secret. The agent does not hold Azure tokens: Azure MCP moves out of the agent into its own Container App that performs on-behalf-of itself, and the agent presents a user token scoped to that server, fetched per Task from the web app. Handing the agent an ARM token was rejected because model-written shell commands share the agent's process space and an ARM token carries the user's write rights. Keeping the agent on its own read identity with a pre-check was rejected because the agent could read more than the user. Foundry's native agent-on-behalf-of-user route was not used because it is preview and several behaviours are undocumented; it becomes the target when it is generally available. This supersedes the read-role part of ADR 0004: the agent identity has no Azure roles.
