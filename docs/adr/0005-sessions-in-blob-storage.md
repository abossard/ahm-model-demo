# Sessions live in Blob Storage

Sessions, Tasks, results and activity timelines are stored as blobs in one private container: a JSON blob per Session and Task, and an append blob per timeline. PostgreSQL was the first choice, but its only other user, the request journey, was removed, and a database server for a few documents is the slowest and most expensive resource in the deployment. Foundry conversations were rejected as the record because they expire when idle and a caller cannot list them as shared Sessions. Table Storage was rejected because a health model diff can exceed its entity size limit. The store has no delete operation, so Sessions are never deleted by construction. The cost is no queries: listing Sessions reads one blob per Session, which is fine at demo scale.
