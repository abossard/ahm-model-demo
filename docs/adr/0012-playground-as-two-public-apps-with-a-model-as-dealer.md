# The MCP App Playground is two public apps beside the demo, with a language model as the blackjack dealer

The playground runs as two Container Apps in the demo's environment, `playground` and `playground-mcp`, both reachable from the internet without sign-in, each with an identity of its own. Visitors are anonymous: the browser makes a handle and an id once, keeps them in `localStorage` and sends them as a tool argument. The browser is the MCP host: it runs the SDK client and one `AppBridge` per View, and the host server only relays its requests to the MCP server and records them for the wire drawer. The MCP server is stateless Streamable HTTP and owns everything else: the tools, the five Views as `ui://` resources, the rules, the store and the calls to the model. Both are TypeScript on Node 24, because the host and View halves of MCP Apps exist as TypeScript libraries (`@modelcontextprotocol/ext-apps` 1.7.5, the version the web UI uses). Game rules are calculations with no clock, no randomness and no I/O; one module, `tables.ts`, joins them to the store, the clock and the model.

At the blackjack table a language model is the dealer and code is the referee. The model does two things: it puts the next cards of the shoe in order without knowing who will get them, and it decides hit or stand for the dealer's hand without knowing the next card. Its replies are structured output against a strict JSON Schema, and each is checked before it counts: the cards must be left in the shoe, the count must match, a decision must be legal. Code deals from the ordered cards, adds up hands and pays; it never picks a card and never decides for the dealer. A reply that fails twice, takes longer than eight seconds or exceeds a cap ends the round as a misdeal with every bet returned. The caps are ten model calls a round, 120 a table and hour, and 60 a minute for the whole app.

The demo's web app could not host this. It signs every user in (ADR 0006, ADR 0008), its identity can write health models (ADR 0004), and its session store holds what signed-in users did. A page anyone can open must share none of that, so it has its own apps, its own identities and its own store (ADR 0013). The cost is a second stack in a Python repository, a public page that spends on a model, bounded only by the caps, and a dealer that is a poor source of chance: its habits show in the cards, and the table shows every call it made. Logs go to stdout and Log Analytics only, because Application Insights here accepts Entra tokens and the playground carries no telemetry library.

Rejected: a route in the web app (sign-in, and an identity with health model roles behind a public game); the host server as the MCP client with an API of its own toward the browser (the browser would not speak MCP, and the second hop in the drawer would be a reconstruction); MCP sessions (a session dies with its replica at every deploy, and nothing here needs one, see ADR 0014); a rules engine with a random shuffle and the model as commentary (the point is a model whose output is validated before it has an effect); the model drawing each card when it is needed (it would see the hands and could steer them, and every hit would wait for it); a random draw when the model fails (two dealers with different habits, where a misdeal is one rule a player already knows).
