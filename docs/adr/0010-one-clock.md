# One clock for the whole page

The page has one selected moment, `timelinePinned` in the zustand store: null is now and live, a number is a past instant. The plot of the timeline writes it, at most once an animation frame, and a link restores it (`at=<ISO>`). Everything that shows health reads it and nothing else decides which time is shown: the six graph views are handed the model at the moment (`selectModelAt`: today's entities and relationships with the states and signal values of then, calculated from the time-series store of ADR 0009, with every unchanged entity the same object), and the top bar, the strip of the selected entity, the question, the Outline's last change and the timeline tree read selectors made from the same calculation. A bar under the top bar says which time is shown and returns to now. A question asked at a past moment is an Explain Task with `asOf`, which the web app checks, stores and passes on, and the hosted agent reads the model as it was (`timestamp` on `monitor_healthmodels_inspect`), its history for the 24 hours that end there, and its metrics and logs for that window. What follows the moment in React is rendered through one hook, `useAtMoment`, as one transition a moment, so a view that takes several frames to draw follows a drag a few moments behind and never holds the line up.

Before this, the selected moment changed the timeline's own tree and a list beside it, while the graph, the top bar, the strip and the question kept showing now, and the assistant could be asked about the past only in words. Three things are about now by nature and stay so, and say so. A comparison is a proposal against the model now: opening one returns to now, and selecting a moment closes it. A health report is about now: the button is disabled at a past moment. A model check and a design run for now, and the Ask menu and the form read "as it is now". Live changes that arrive while a past moment is shown are kept and neither announced nor flashed. The cost: the structure at a past moment is today's, so an entity that did not exist then reads Unknown and one that was since removed is not drawn, while the assistant, which reads the model as it was, sees the structure of then; a log query has no end in the tool the agent calls, so the agent rewrites `now()` and `ago()` and refuses a query without an upper bound on `TimeGenerated`, which costs the model a call when it forgets; and a bar that appears and goes moves the page by its height.

Rejected: a second clock for the graph, set with its own control (two times on one page is the mix-up this removes); following the pointer instead of a selected moment (a hover that redraws the page and changes what a question asks is not something to do by passing over the plot); asking the service for the model at every moment with the API's `timestamp` (three list calls a moment, which cannot follow a drag, and the browser holds the histories already; it would give the structure of then); copying the model at the moment into the store on every move (a second copy of the state to keep right, where a calculation with a memory gives the same objects); reading the moment with `useStore` in every view (an external store is rendered at once, so a drag would wait for the largest view each frame); a transition per component (readers that finish at different times show different moments in one frame, and commit three or four times a move); an `asOf` in the Task result (the Task already says it, and two fields can disagree); time travel in Compare, with the base as it was (the proposal is against a base captured when its Task started, so a third time would be on screen); letting a model check run at a past moment (its changes are applied to the model now, and Apply refuses a base that is not the live one).
